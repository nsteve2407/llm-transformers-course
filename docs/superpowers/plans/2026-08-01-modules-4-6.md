Implement, in order:
1. **Scaled dot-product attention function**: takes Q, K, V of shape `(batch, heads, seq, d_k)` and an optional additive mask (shape broadcastable to `(batch, heads, seq, seq)`, containing 0 or -inf), computes `softmax(QK^T/√d_k + mask)V`. Numerically stable (subtract max before softmax, or rely on PyTorch's `softmax` which already does this).
2. **`MultiHeadAttention` module**: separate learned Q/K/V linear projections (`d_model → d_model`), reshape into `(batch, heads, seq, d_k)`, call the attention function, reshape back and apply an output projection. Support both self-attention (Q=K=V=same input) and cross-attention (Q from one input, K/V from another) via the module's call signature.
3. **Positional encodings**: implement sinusoidal PE as a fixed (non-learned) buffer, AND a learned PE as an `nn.Embedding` over position indices — expose both behind a flag so the learner can compare.
4. **Encoder block**: self-attention → residual → LayerNorm → position-wise FFN (`d_model → d_ff → d_model` with ReLU, `d_ff = 4 * d_model`) → residual → LayerNorm, implemented in BOTH Post-LN (`LN(x + Sublayer(x))`) and Pre-LN (`x + Sublayer(LN(x))`) configurations behind a flag.
5. **Masking**: build a causal/look-ahead mask (upper-triangular -inf) and a padding mask from a toy batch with variable-length sequences (pad tokens), and combine them correctly when both apply.
6. **Validation against PyTorch's own implementation**: copy your `MultiHeadAttention`'s learned weights into an `nn.MultiheadAttention` instance (matching `in_proj_weight`/`out_proj` parameter layout — this requires understanding how PyTorch packs the QKV projection weights) and confirm `torch.allclose` agreement on a random input; similarly compare your full Post-LN encoder block against `nn.TransformerEncoderLayer` with copied weights.
7. **Visualization**: plot an attention-weight heatmap for a toy sentence (e.g. using `matplotlib.pyplot.imshow`) for one head.
8. **Causal-mask verification**: empirically confirm that changing a future token's input embedding does not change an earlier position's output when the causal mask is applied (a concrete, checkable proof the mask works, not just visual inspection).
9. Closing markdown cell summarizing what was implemented and validated.

No `SMOKE_TEST` branch is strictly necessary here (no external dataset download — everything is synthetic tensors), but keep cell execution fast (small `d_model`, e.g. 64, `seq_len` ~16, `batch` ~4) so the notebook runs in well under a minute either way.

# Module 6: Scaling & Modern LLMs

Scaling laws, RoPE, RMSNorm, SwiGLU, GQA, BPE tokenization, nanoGPT build.

## Subtopics

- Kaplan et al. power-law scaling of loss with N/D/C; sample efficiency of larger models
- Chinchilla's compute-optimal N/D reallocation and why GPT-3-era models were undertrained
- LLaMA's deliberate "overtraining" beyond compute-optimal N for inference efficiency
- RoPE: rotating query/key vector pairs to encode relative position via rotation matrices
- RMSNorm: dropping LayerNorm's re-centering term, normalizing only by RMS statistic
- Pre-norm vs. post-norm placement of RMSNorm
- SwiGLU feed-forward blocks and the ~8/3·d_model hidden-dim rescaling LLaMA uses to match param count
- MHA → MQA → GQA: shared KV heads across query-head groups, KV-cache/throughput tradeoff
- BPE tokenization: iterative merging of most-frequent adjacent symbol pairs; byte-level variants
- Putting it together: LLaMA = decoder-only Transformer + RoPE + RMSNorm (pre-norm) + SwiGLU + (larger variants) GQA
- Practical consequences for training stability, KV-cache size, and inference cost
